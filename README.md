# FSA RAL — облачное распознавание действующих аккредитлиц

Пилот на 5 файлах (см. `PR #1`, смёржен) подтвердил: облачная сессия Claude Code
(Sonnet vision) даёт кратно лучшую структурную разбивку, чем локальный `qwen2.5vl:7b`
(`norm_doc`/`object`/`indicator` — 0% null против 71-82% у локального). Теперь —
масштаб на реальный объём: **1993 uuid** в `target_uuids.txt` — это ВСЕ документы со
статусом «Действует» в реестре ФСА, которые ещё НИ разу не обрабатывались (ни локально,
ни в облаке). Архивные и записи с неясным статусом сюда не входят — их независимо
добивает локальный пайплайн, не пересекается с этой задачей.

## ⚠️ Бюджет ограничен — читай перед стартом

Промо-кредит Anthropic на конец пилота — **~$245 из $250**. По факту пилота
(~$0.02/страница) и оценке объёма (медиана 5 стр/файл, но есть тяжёлый хвост —
попадаются документы на сотни страниц) — реальная стоимость всех 1993 файлов может
превысить оставшийся кредит. **Это ожидаемо и нормально, не ошибка.** Когда кредит
подходит к концу (Стас видит это на своей странице https://claude.ai/settings/usage
или в баннере окружения) — сессию просто останавливают, а недообработанные uuid
остаются на следующий заход (с новым/пополненным бюджетом или локальным пайплайном).

**Поэтому — работай инкрементально, не пакетно.** После КАЖДОГО обработанного файла:
закоммить и запушить `results/{uuid}.json` сразу же (маленькие коммиты, не один
гигантский в конце). Если сессию прервут на файле 400 из 1993 — 399 уже должны быть
в гите, не потеряны.

## Как скачать один PDF

```bash
curl -s -H "X-Pdf-Token: $PDF_SERVE_TOKEN" \
  "https://api4.notifikatai.ru/fsa-checker/pdf/{uuid}" \
  -o "{uuid}.pdf"
```

Токен уже в переменных окружения сессии (настроено на стороне Стаса). Эндпоинт
read-only, 403 без токена, 404 на несуществующий uuid. `pdfinfo` в облачном окружении
НЕ установлен — считай страницы и рендерь через PyMuPDF (`fitz`), как в пилоте.

## Порядок работы

1. Прочитай `target_uuids.txt`. Вычти из него те uuid, для которых уже есть
   `results/{uuid}.json` в репозитории (резюме после прерванной сессии — не переделывай
   готовое).
2. Обрабатывай остаток по одному (или пачками по 5 параллельно, как в пилоте — это
   давало хорошую скорость: 250 страниц/5 файлов за 13 минут). Для каждого uuid:
   - скачай PDF (см. выше);
   - определи число страниц через PyMuPDF;
   - пройди ВСЕ страницы визуально (Claude vision, не текстовый слой — сканы чистые);
   - распознай таблицу "Область аккредитации" по схеме ниже;
   - удали PDF и рендеры (не коммить бинарники);
   - **сразу закоммить и запушить** `results/{uuid}.json` в ветку (см. ниже про ветку).
3. Продолжай, пока не кончится список ИЛИ пока тебя не остановят / не кончится кредит.
4. По ходу работы можно открыть PR рано (после первых 10-20 файлов) и просто пушить
   новые коммиты в ту же ветку — PR обновится сам, не нужно ждать конца списка.

## Ветка

Работай в новой ветке `claude/active-batch` (не в `claude/dreamy-dirac-rmzimd` — та уже
смёржена и закрыта пилотом). Если ветка уже существует (продолжение прерванной сессии) —
просто продолжай коммитить в неё, не начинай заново.

## Схема результата (не менять, стабильна после пилота)

```json
{
  "uuid": "<без .pdf>",
  "pages_read": <int, реально пройдено страниц>,
  "pages_total": <int>,
  "rows": [
    {
      "raw_row_text": "весь текст строки как есть, колонки через |",
      "norm_doc": "текст или null",
      "object": "текст или null",
      "indicator": "текст или null",
      "okpd2_code": "текст или null",
      "tnved_code": "текст или null",
      "range_from": "текст или null",
      "range_to": "текст или null",
      "unit": "текст или null",
      "tr_section": "ближайший заголовок раздела над строкой (напр. \"ТР ТС 020/2011\"), иначе null"
    }
  ],
  "issues": "текстовое описание проблем/оговорок, или null если всё прошло чисто"
}
```

`raw_row_text` — обязателен всегда. Не выдумывай данные — если что-то не читается,
`null` + опиши в `issues`, не гадай. Если у одной пронумерованной строки таблицы
несколько показателей/диапазонов — отдельная JSON-строка на каждый, с повтором
`norm_doc`/`object`/кодов (так делали в пилоте, это правильно).

## Периодические отчёты

Каждые ~50-100 обработанных файлов — короткое сообщение в сессии: сколько сделано из
1993, средняя цена/файл на этом отрезке (если видно usage), любые системные проблемы
(не разовые оговорки по одному файлу — те просто пиши в `issues` самого файла).

# FSA RAL — пилот облачных Claude Code сессий

Пилотный проект: проверить, может ли облачная сессия Claude Code (Anthropic cloud VM,
не локальный GPU) распознавать таблицу "Область аккредитации" из PDF-сканов реестра
Росаккредитации (ФСА) лучше, чем наш локальный пайплайн на `qwen2.5vl:7b`.

Контекст: `10-Активные-проекты/14. Чекер реестра ФСА/` в Obsidian-хранилище Стаса.
У локального пайплайна нашлась системная проблема — 55% извлечённых строк содержат
только `raw_row_text` (сырой текст), структурные поля (норм.документ/объект/коды
ОКПД2/ТН ВЭД/диапазон) почти всегда `null`, даже когда в тексте строки эти данные
явно присутствуют. Гипотеза: Claude (Sonnet) справится с этим разбором на порядок
лучше локальной 7B vision-модели.

## Почему PDF НЕ лежат в этом репозитории

Официальный лимит облачных сессий: bundled-репо (без GitHub App) — до 100MB, VM —
30GB диска. Пдфки качаются НА ЛЕТУ через маленький HTTP-эндпоинт на нашем сервере
(NL1), не хранятся в git вообще. Каждая сессия обрабатывает один PDF за раз,
результат — маленький JSON/markdown в `results/`.

## Как скачать один PDF внутри сессии

```bash
curl -s -H "X-Pdf-Token: $PDF_SERVE_TOKEN" \
  "https://api4.notifikatai.ru/fsa-checker/pdf/{uuid}" \
  -o "{uuid}.pdf"
```

`PDF_SERVE_TOKEN` должен быть доступен как переменная окружения сессии (см. ниже,
как это настроить со стороны Стаса в claude.ai — облачная сессия сама сделает
запрос, куда токен подставит прокси Anthropic, если он добавлен как **API
credential** на хост `api4.notifikatai.ru`; либо просто как обычная переменная
окружения окружения — тогда сессия увидит его значение напрямую, это ок для пилота).

Эндпоинт read-only, отдаёт ровно один файл по строгому uuid-паттерну, ничего не
пишет. 403 без правильного токена, 404 на несуществующий uuid.

## Задача для этого пилота

В `target_uuids.txt` — 5 uuid документов, которые наш локальный пайплайн НЕ смог
дочитать целиком (упёрлись в лимит 40 страниц/420 секунд, реальный объём — 50
страниц каждый). Для каждого uuid:

1. Скачай PDF по инструкции выше.
2. Определи число страниц (`pdfinfo` уже установлен в облачном окружении Claude
   Code по умолчанию — или просто открой PDF и посмотри).
3. Пройди ВСЕ страницы (не только первые 40 — в этом весь смысл пилота: локальный
   пайплайн уже проверен, у него именно этот потолок и ломается).
4. Для каждой страницы визуально распознай таблицу "Область аккредитации" —
   колонки обычно: № / нормативный документ (ГОСТ/ТУ/методика) / объект испытания /
   код ОКПД2 / код ТН ВЭД / показатель / диапазон измерения (от-до) / единица
   измерения. Не все колонки есть всегда, порядок/названия плавают год от года.
5. Некоторые документы группируют строки таблицы под заголовками разделов
   (например "ТР ТС 020/2011") — если видишь такую структуру, для каждой строки
   указывай ближайший заголовок раздела НАД ней (`tr_section`), иначе `null`.
6. Сохрани результат в `results/{uuid}.json` СТРОГО по схеме ниже.
7. Удали скачанный PDF (не коммить бинарники в репо).
8. Закоммить и запушь результаты, открой PR.

## Схема результата (обязательна, для совместимости с локальным пайплайном)

```json
{
  "uuid": "<без .pdf>",
  "pages_read": <int, реально пройдено страниц>,
  "pages_total": <int, из pdfinfo>,
  "rows": [
    {
      "raw_row_text": "весь текст строки как есть, колонки через |",
      "norm_doc": "текст или null",
      "object": "текст или null",
      "indicator": "текст или null",
      "okpd2_code": "текст или null",
      "tnved_code": "текст или null",
      "range_from": "текст или null",
      "range_to": "текст или null",
      "unit": "текст или null",
      "tr_section": "ближайший заголовок раздела над строкой или null"
    }
  ],
  "issues": "текстовое описание проблем, или null если всё прошло чисто"
}
```

`raw_row_text` — обязателен всегда, даже если остальные поля не разложились по
колонкам. Не выдумывай данные — если что-то не читается, `null`, не гадай.

## После пилота

Отчитайся коротко в PR-описании: сколько времени/токенов ушло на 5 файлов
(смотри в самой сессии на claude.ai — там видно usage), какого качества результат
по сравнению со схемой выше (особенно: много ли `null` в структурных полях —
это ключевая метрика, ради которой весь пилот). Решение "стоит ли продолжать
облачными сессиями на весь хвост" примем по факту этих цифр, не раньше.
